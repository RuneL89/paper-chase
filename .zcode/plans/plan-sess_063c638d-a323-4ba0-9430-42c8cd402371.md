## Goal
Make JSON parse failures recoverable via an LLM "corrector agent" whose targeted instruction feeds the existing feedback-reask loop, generalized across all JSON-producing stages; and close the two transport holes that hung the ingest overnight. (User approved this plan in conversation; the corrector routes to a new `jsonCorrector` slot falling back to the Default slot — currently DeepSeek-V4-Pro.)

## A. Shared LLM-based JSON corrector
- New `src/llm/json-corrector.ts` exporting `diagnoseJsonParseFailure({ rawResponse, errorMessage, context, truncated, logPath })` → targeted fix instruction string, or `null` on any corrector-side failure (loop then falls back to today's generic block; corrector can never break the pipeline).
- New prompt file `prompts/json-corrector.prompt.txt` with evidence-bounded inputs: parse error message; ±800-char window around the byte position when the error names one; head+tail (~1500 chars each) for truncated/large outputs; full output when <4000 chars. Truncation flag instructs "shorten free-text fields, keep all items, return complete JSON".
- Corrector call: `callType: 'json-corrector'`, `maxRetries: 1`, `maxTokens: 2048`, `temperature: 0`, log context `<ctx>#json-diagnosis`.
- `src/llm/reask.ts`: `validate` becomes optionally async; new optional `feedbackEnhancer(output, errors, attempt)` hook appends a `Diagnosed cause and fix:` section to the correction block and may supply an `echoOverride` (tail-only echo for truncated outputs). Default behavior byte-identical when hook absent.

## B. Wire into JSON-producing stages
- Extractor (`src/agents/extractor.ts`): validator awaits corrector on parse failure; truncation flag from stored finish reason; 3-attempt budget + fail-loud exhaustion unchanged.
- Curation (`src/agents/curation.ts`, `curateSingleCall`): same wiring — fixes truncation blind spot and full-echo doubling on large buckets.
- Cross-wiki (`src/cross-wiki/llm.ts`, `runCrossWikiJsonCall`): same wiring; never-abort degrade preserved.
- Synthesis, DOX Writer, AGENTS.md Updater: unchanged (markdown outputs with already-verbatim-targeted validators).

## C. Transport hardening (`src/llm/client.ts`)
- Absolute per-attempt deadline via `AbortSignal.timeout`: 15 min when `maxTokens >= 32768`, else 5 min; timeout lands in the existing network-error path (≤3 attempts, 5/15/45s backoff).
- Clamp honored `Retry-After` (seconds and HTTP-date forms) to ≤90 min (top ladder rung); DOX closeout records this as an amendment to the 2026-08-20 Retry-After preference.
- Surface provider stop reason (`finish_reason`/`stop_reason`) via `onResponseMeta` callback so validators detect truncation deterministically.

## D. Routing
- New `jsonCorrector` slot in ModelRouting + persisted `models.jsonCorrector` in `.paper-chase.json` (legacy → null, fallback to default slot) + "JSON Corrector Model" row in TUI Settings following the per-step provider+model pattern.

- Client: Retry-After clamp; timeout → network-error classification; finish-reason plumbing.
- Integration: extractor control-character recovery with mocked corrector; curation truncation tail-echo; cross-wiki parse recovery/degrade.
