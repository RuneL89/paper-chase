# src/ — DOX contract

## Purpose

All TypeScript source for LLM Wiki CLI v2.0: CLI entry point, TUI (Ink), PDF extraction, LLM client, the Extractor agent (Layer 2), schema validation, commands, state, utilities, and (in later phases) Materializer/DOX Writer agents.

## Ownership

* `cli.ts` — Commander entry point; named `program` export; `program.parse()` only runs when executed directly (guarded), never on import; `ingest` accepts `--no-extract` (Layer-1-only opt-out; extraction is default-on since Phase 2) and `--no-dox-llm` (deterministic-DOX opt-out; the LLM DOX Writer is default-on for CLI runs since Phase 6)
* `tui/` — Ink TUI: `app.tsx` (screen router), `menu.tsx` (main menu + exported `resolveMenuSelection`), `init-screen.tsx` (Title + Workspace only; slug derived from Title via `slugify`), `ingest-screen.tsx` (passes `doxLlm: true` since Phase 6 — production ingests are LLM-driven), `add-pdfs-screen.tsx`, `extractor-test-screen.tsx`, `entity-browser.tsx`, `topic-browser.tsx`, `dox-browser.tsx` (picker opens at the workspace level: `index-of-indexes.md` above the per-wiki entries), `validation-report-screen.tsx`, `test-screen.tsx`, `settings-screen.tsx`, `components/` (header, footer, spinner, error-box, success-box, tree-browser with optional `workspaceFile` picker entry), `hooks/use-wiki-list.ts`, `hooks/use-wiki-details.ts`, `hooks/use-raw-contents.ts`, `hooks/use-document-chunks.ts`
* `extraction/pdf.ts` — `extractText(pdfPath, startPage?, endPage?)` via pdfjs-dist legacy build; never splits a page; additive Phase 1 `getPageCount(pdfPath)` shares the same loader
* `extraction/markdown-tables.ts` — deterministic plaintext-table detection; rebuilds markdown tables from whitespace-collapsed extraction output (conservative guards, every word preserved)
* `llm/client.ts` — `callLLM(prompt, system?, options?)`; Anthropic Messages API; logs `LLM Call | Tokens: i/o | Cost: $x` for every call; no retries, throws on failure; additive Phase 2 `CallLLMOptions { maxTokens?, temperature? }` — defaults (1024, temperature omitted) preserve the frozen Phase 0 behavior exactly; additive Phase 5 `callType` and `logPath` options so each LLM call can be tagged and appended to `wikis/<slug>/.state/llm-calls.json`
* `utils/hash.ts` — `sha256(filePath)` streaming helper
* `utils/slug.ts` — wiki-slug validation (kebab-case), source-slug derivation, and `slugify` (also used by the Extractor for deterministic slug normalization)
* `utils/aliases.ts` — Obsidian wikilink aliases (UAT 6.3 fix, user decision 2026-07-19 Option A): `aliasesForTitle(title, fileSlug)` returns `[title]` when the title differs from the file basename (case-insensitive) and `undefined` otherwise; `enforceAliasesInMarkdown(markdown, title, fileSlug)` re-imposes the field over a fully-rendered page (used for LLM-written synthesis output; pages without a frontmatter block are returned unchanged). Used by every page writer: entity/topic/source pages, the ingest document-page writer (always a no-op there: title == chunk id), and the DOX Writer's deterministic index frontmatter (both deterministic and LLM-enforced paths; index pages always carry their folder/wiki title as the alias). Since the 2026-07-20 pipe-form change, aliases are retained as Obsidian search/suggester aids only — link resolution no longer depends on them
* `utils/wikilinks.ts` — Obsidian-native wikilink forms (user directive 2026-07-20, compliance-log entry [2026-07-20 00:15]): `formatWikilink(target, display?)` builds `[[target|Display]]` or the bare `[[target]]` when the display is missing or equals the target exactly (Obsidian's own display==target behavior); `parseWikilinkTarget(inner)` splits a link's inner text on the FIRST `|` (targets never contain spaces/pipes in our wikis). Conventions: content pages `[[<basename>|<Title>]]`, folder indexes `[[<folder-path>/index|<Title>]]`, wiki root `[[index|<Wiki Title>]]`. The single home for link formatting/parsing — used by the entity/topic page writers, the DOX Writer (catalogs, prompt link targets, repair), and the link checker
* `utils/paths.ts` — workspace/wiki path helpers; generated paths always use forward slashes
* `utils/file-dialog.ts` — native graphical PDF picker (user decision 2026-07-17 10:55): `pickPdfFiles()` spawns `powershell.exe -NoProfile -NonInteractive -Command <script>` (`shell: false`, args array only) showing a topmost System.Windows.Forms OpenFileDialog (PDF filter, multi-select, 10-minute timeout); resolves with the picked paths, `null` on cancel, throws descriptively on spawn/non-zero-exit/timeout; `parseDialogOutput(stdout)` is the pure `\r\n`-safe parser exported for tests
* `commands/init.ts` — Phase 1 `init(slug, { title?, workspace? })`: creates `wikis/<slug>/` structure and generates AGENTS.md from `templates/AGENTS.md` (all `{{WIKI_TITLE}}`/`{{SLUG}}` replaced)
* `commands/ingest.ts` — `ingest(slug, { workspace?, pagesPerChunk?, extract?, synthesis?, doxLlm?, onProgress?, extractChunkFn?, synthesizeEntityFn?, synthesizeEntityPermissiveFn?, synthesizeTopicFn?, synthesizeTopicPermissiveFn?, writeDoxIndexFn?, writeWorkspaceIndexFn?, outputLanguage? })`: hash-skip unchanged PDFs, page-by-page extraction, whole-page chunking (default 5), document pages via gray-matter, source pages, state; Layer 2 since Phase 2: per-chunk Extractor run (default-on, `extract?: boolean` opt-out) saving `.state/extracted/<chunk-id>.json`, additive `IngestResult.extractions` counts; Phase 5: after materialization, optionally runs the Synthesis Writer per entity and topic page in that order (opt-in `synthesis?: boolean`, default false), writing synthesized pages only when the preservation check passes; Phase 6 pipeline order (phase doc §3.5): synthesis → `validateWiki()` (content validation, additive `IngestResult.validation`) → `writeDoxContracts()` → `validateWiki()` again (final validation covering the DOX pages, additive `IngestResult.finalValidation`; the persisted `validation-report.json` reflects the final pass) → `writeWorkspaceIndex()` (2026-07-20 amendment: regenerates `wikis/index-of-indexes.md` from every wiki's freshly-written root contract, at the end of every ingest); `doxLlm?: boolean` (default false) and the test-only `writeDoxIndexFn`/`writeWorkspaceIndexFn` pass straight through to the DOX Writer; `outputLanguage?` (English default) feeds the workspace pass prose language (Phase 7 hook); with `extract: false` there is a single DOX pass and no validations; `extractChunkFn` and the `synthesize*Fn` injections are optional test-only helpers for LLM-free runs
* `commands/extract-chunk.ts` — Phase 2 `extractDocumentChunk(wikiDir, chunkId)`: the single shared extraction path used by both `ingest` and the TUI Test Extractor screen; reads the document page (chunk text, page range, source file from frontmatter), the wiki constitution, and rolling memory (read-only); writes `.state/extracted/<chunk-id>.json`
* `commands/add-pdf.ts` — user-directed Phase 1 extension (2026-07-17): `addPdfToWiki(wikiDir, sourcePath)` copies a PDF into `<wikiDir>/raw/` (strips surrounding quotes from drag-drop pastes, validates existence + `.pdf`, keeps the file name); throws typed `AddPdfError` with user-displayable messages; no LLM, no new deps
* `state/ingestion-state.ts` — read/write `wikis/<slug>/.state/ingestion.json` (phase doc §2.3 shape)
* `state/rolling-memory.ts` — Phase 2 read-only loader and Phase 3 writer for `.state/rolling-memory.json` (vision `04` §5 shape: `folderStructure` → folders, `entities[].slug` → slugs; absence → empty lists, malformed → descriptive throw)
* `state/conflicts.ts` — Phase 5: logs entity/topic/document preservation-check failures to `wikis/<slug>/.state/conflicts.json`
* `state/synthesis-report.ts` — Phase 5: `logSynthesisReport(wikiDir, entry)` writes a `synthesis-report.json` entry for each entity, topic, and document page showing the strict/permissive/structured-template fallback chain
* `pages/source-page.ts` — deterministic `sources/<source-slug>.md` provenance pages (phase doc §2.4)
* `pages/entity-page.ts` — deterministic `entities/<subfolder>/<slug>.md` writer with YAML frontmatter, mentions, relationships, claims, and `[^srcN]` citations (phase doc §2.1); relationship/claim entity links render in Obsidian-native pipe form `[[slug|Title]]` via `utils/wikilinks.ts` (bare `[[slug]]` fallback for unknown slugs)
* `pages/topic-page.ts` — deterministic `topics/<subfolder>/<slug>.md` writer grouped by claim type (phase doc §2.2); Phase 5 additive: optional `entities` and `context` fields for topic synthesis; claim entity links use the same pipe form as the entity-page writer
* `pages/document-page.ts` — Phase 5: `DocumentPageData` interface for document-page synthesis (chunk title, source, page range, extracted text, entity slugs, and claims)
* `materializer.ts` — deterministic Layer 3: reads `.state/extracted/*.json`, aggregates entities/topics, writes pages, updates rolling memory (phase doc §2.3); Phase 5 additive: returns `MaterializeResult` with `EntityPageData`, `TopicPageData`, and `DocumentPageData` for each page so the Synthesis Writer can use them without re-parsing markdown
* `dox-writer.ts` — the DOX Writer, Layer 5 (Phase 6): scans `wikis/<slug>/` (excluding `raw/` and `.state/`), builds a tree of folders and markdown files, and writes `index.md` navigation contracts for every folder plus the wiki root. Two modes: deterministic (default, `doxLlm` absent/false — generic template descriptions, no LLM calls, byte-stable behavior) and LLM-driven (`doxLlm: true` — one LLM call per folder plus the root via `prompts/dox-writer.prompt.txt`, `callType: 'dox-writer'`, `maxTokens: 2048`, folder context includes children, statistics, full contents of the folder's OWN direct pages, the wiki AGENTS.md, and rolling memory). Bottom-up synthesis (user-directed 2026-07-19 refinement): folders are processed deepest-first post-order at every level, and every folder with child folders — the root included — also receives `childIndexes` (the freshly-written full `index.md` of each direct child folder, written earlier in the same run) so parents synthesize a summary-of-summaries; the root's top-folder indexes flow through the same `childIndexes` mechanism. Catalog rule: the `## Pages` section catalogs direct pages AND child folders; a folder with sub-folders but zero direct pages still catalogs its child folders instead of emitting "No pages in this folder." All catalog/navigation links use the Obsidian-native pipe form (user directive 2026-07-20): pages `[[<basename>|<Title>]]`, child/parent/sibling folder indexes `[[<folder-path>/index|<Title>]]`, wiki-root parent `[[index|<Wiki Title>]]` — implemented via `utils/wikilinks.ts`. Wikilink safeguard (2026-07-19 refinement, pipe-form rework 2026-07-20): the prompt supplies the exact resolvable pipe-form link for every catalog/navigation target (`linkText` computed deterministically; additive `parentLinkText`/`siblingLinkTexts` context fields), and the LLM body is post-processed before writing — every `[[...]]` is tested with semantics mirrored from `validation/link-checker.ts` (path map + slug map + folder-index/root fallbacks); pipe-form links with resolvable targets are kept verbatim, resolvable-but-bare legacy links are NORMALIZED to the canonical pipe form, unresolvable links that uniquely match a page title (case-insensitive) are rewritten to that page's canonical pipe form, and anything else is de-linked (brackets stripped, display text kept); one summary warn line per folder at most. Deterministic enforcement over the LLM output (vision `03` §6): the LLM's frontmatter is always discarded (title, type, wiki, updated, children are re-imposed) and its `## Statistics` section is replaced with the deterministic counts; unparseable output or missing required sections falls back to the deterministic body, and any LLM failure (missing key, network) falls back per folder — a missing key never crashes an ingest. `writeDoxIndexFn` (test-only) replaces the LLM call; `logPath` defaults to `<wiki>/.state/llm-calls.json`. Never creates folders, moves pages, writes content pages, or decides taxonomy. **Workspace pass (2026-07-20 user-ratified amendment):** `writeWorkspaceIndex({ workspace?, doxLlm?, writeWorkspaceIndexFn?, outputLanguage?, logPath? })` regenerates `wikis/index-of-indexes.md` at the end of every ingest — the topmost parent in the same bottom-up chain (folder indexes → wiki root index → workspace index). Its ONLY content input is each wiki's freshly-written root `index.md` (never the wikis' content pages); wikis without a root index are skipped and zero wikis writes nothing. Same rules as per-folder indexes: LLM prose via `prompts/dox-writer-workspace.prompt.txt` in `doxLlm` mode, deterministic children (`<slug>/index.md` per wiki) + statistics (wiki count + corpus totals) + frontmatter re-imposed (no `wiki` field — it governs all wikis), deterministic fallback on LLM failure, wikilink safeguard with `[[<slug>/index|<Title>]]` pipe forms. Prose language follows the triggering ingest's `outputLanguage` (English default until Phase 7)
* `validation/link-checker.ts` — Phase 4: deterministic wikilink check; reports broken links and orphaned pages (excludes `index.md`, `sources/*.md`, and the wiki constitution `AGENTS.md`); Phase 5 additive: folder indexes resolve as `[[Folder Name]]` so DOX navigation links work; 2026-07-20 pipe-aware semantics: the part before the first `|` is the resolution target, matched by exact vault-relative path (without `.md`, suffix tolerated) first, then by the slugified-basename map with the folder-index/wiki-root fallbacks — legacy bare forms (`[[Page Title]]`, `[[slug]]`, `[[Folder Name]]`) stay resolvable for older wikis
* `validation/citation-checker.ts` — Phase 4: deterministic `[^srcN]` citation check; requires a matching definition in the page and a source PDF in `raw/`
* `validation/schema-validator.ts` — Phase 4: deterministic YAML frontmatter check (`title`, `type`, `updated`) using `gray-matter`; excludes the wiki constitution `AGENTS.md`
* `validation/index.ts` — Phase 4: `validateWiki()` aggregator and `logValidation()` console reporter; additive Phase 5 file logging: `logValidation(summary, wikiDir?)` also writes `wikis/<slug>/.state/validation-report.json`, and `writeValidationReport(wikiDir, summary)` writes the same file without console output
* `agents/extractor.ts` — Phase 2: the Extractor (Layer 2). `extractChunk(chunkText, pageRange, sourceFile, agentsMd, existingFolders, existingEntities)` → extended `ExtractorResult` (entities/relationships/claims + `timeline`, `context`, per-entity `significance`, optional `disambiguation` — gates 2.9-2.12 extension); typed `ExtractorError` (raw response on invalid JSON, issue list on schema failure; NO retry); fence-tolerant JSON parse; deterministic `slugify()` normalization of all slugs before validation; extraction calls use `maxTokens: 4096, temperature: 0`
* `validation/extractor-schema.ts` — Phase 2: non-throwing `validateExtractorResult(data, pageRange?)` → `{ valid, issues }` per phase doc §2.4 + extended fields; folder prefix `^entities/|^topics/`, no `..`, ≤4 segments, page-range checks (skipped for unparseable ranges)
* `validation/preservation-check.ts` — Phase 5: `checkPreservation` (entity) and `checkTopicPreservation` (topic) verify synthesis did not drop any mention context, relationship evidence, claim text, or existing source citation
* `agents/synthesis.ts` — Phase 5: the Synthesis Writer (Layer 4). `writeEntitySynthesis` and `writeTopicSynthesis` read their type-specific prompts (`synthesis.prompt.txt`, `synthesis-topic.prompt.txt`), inject page data + wiki constitution, and call `callLLM(prompt)` with 8192 max output tokens; output is a two-layer markdown article with synthesis at the top and preserved detail sections below. Additive permissive fallbacks: `writePermissiveEntitySynthesis` and `writePermissiveTopicSynthesis` read the corresponding permissive prompts and allow the model to summarize in Layer 1 while preserving the exact structured data in Layer 2; used by `ingest.ts` when strict synthesis fails preservation. Document pages are not synthesized because full verbatim extracted-text preservation is impractical for real chunks; they keep their deterministic Phase 1 format.
* `agents/` — Phase 2 landed `extractor.ts`; Phase 5 adds `synthesis.ts` (the Synthesis Writer, Layer 4); the Materializer (Phase 3) is deterministic code in `src/materializer.ts`, not an agent in this folder; the DOX Writer (Phase 6) lives in `src/dox-writer.ts`

## Local Contracts

* Phase 0 public surface is frozen per `Implementation Plan/PHASE_00_infrastructure.md` §7: `extractText`, `callLLM`, `sha256`, and the TUI framework must not change signature/behavior after Phase 0 approval; later phases extend, they do not break (Phase 1's `getPageCount` and Phase 2's `CallLLMOptions` are additive extensions with identical defaults)
* `agents/` holds only the agents whose phase has run (Phase 2: the Extractor; Phase 5: the Synthesis Writer); the Materializer is deterministic code in `src/materializer.ts`; DOX Writer and any rolling-memory writes may not land outside their phases
* LLM calls in the pipeline (all via `callLLM`, all logged): the Extractor (Layer 2, per chunk), the Synthesis Writer (Layer 4, opt-in Phase 5), and the DOX Writer (Layer 5, Phase 6 `doxLlm` mode, per folder plus the wiki root, plus one workspace-pass call per ingest for `wikis/index-of-indexes.md`); every other concern (folder creation, page writing, memory updates) is deterministic code
* Page types are declared in frontmatter; known built-in types are `entity`, `topic`, `document`, `source`, `raw`, and `index` (added in Phase 6)
* Wikilink form contract (user directive 2026-07-20, superseding the bare title-form convention; compliance-log entry [2026-07-20 00:15]): every wikilink the CLI writes uses Obsidian's native target-plus-display pipe form — content pages `[[<basename-without-.md>|<Title>]]` (basename only, no folder path), folder indexes `[[<folder-path>/index|<Title>]]`, wiki root `[[index|<Wiki Title>]]`, bare `[[target]]` only when display equals the target exactly. The single implementation is `utils/wikilinks.ts` (`formatWikilink`/`parseWikilinkTarget`); the link checker resolves the pre-pipe target by exact vault-relative path first, then the slugified-basename map, keeping legacy bare forms resolvable for older wikis
* Frontmatter `aliases` rule (UAT 6.3 fix, 2026-07-19): every page writer adds `aliases: [<title>]` when the page title differs from the file basename (case-insensitive) and omits it otherwise; the single implementation is `utils/aliases.ts` and LLM-written synthesis output gets the field re-imposed deterministically at write time (the model's frontmatter is not trusted for it). Since the 2026-07-20 pipe-form change, aliases are kept as Obsidian search/suggester aids — they are no longer the link-resolution mechanism
* LLM provider is Anthropic (user decision 2026-07-17): key from `ANTHROPIC_API_KEY` with `.env` fallback, model from `ANTHROPIC_MODEL` (default `claude-haiku-4-5-20251001`), prices overridable via env
* Every LLM call must log tokens and cost; product LLM spend is tracked per phase in `.state/phase-N-status.json`
* TUI conventions (Ink 7): every `useInput` is gated `isActive: isRawModeSupported === true`; components must render correctly in non-TTY contexts (static fallbacks); Escape = back, Enter = select
* Native-picker contract (user decision 2026-07-17 10:55, binding for the Add PDFs screen): the PRIMARY way to add PDFs is the OS-native graphical file picker (`utils/file-dialog.ts`); typed/pasted path entry is a demoted FALLBACK only, kept for environments where the dialog cannot run. Cancelling the dialog is neutral ("No files selected."), never an error; input is gated while the dialog/copy is in flight
* Windows shellout rule: spawn with an args array and `shell: false`, never string-concatenated shell commands (see `utils/file-dialog.ts`); the one sanctioned exception is spawning `.cmd` shims like npm, which requires `shell: true` on Windows (EINVAL guard, `tui/test-screen.tsx`)
* ESM only (`"type": "module"`); strict TypeScript; no new dependencies without recording the reason in the phase status file
