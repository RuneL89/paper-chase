# src/ — DOX contract

## Purpose

All TypeScript source for LLM Wiki CLI v2.0: CLI entry point, TUI (Ink), PDF extraction, LLM client, the Extractor agent (Layer 2), schema validation, commands, state, utilities, and (in later phases) Materializer/DOX Writer agents.

Deterministic enforcement over the LLM output (vision `03` §6): the LLM's frontmatter is always discarded (title, type, wiki, updated, children are re-imposed) and its `## Statistics` section is replaced with the deterministic counts; Phase 7 v1.1.0: the folder/root/workspace LLM paths share `runDoxLlmWithRetries` (≤3 total attempts on exceptions or unparseable/missing-section output) before the per-target deterministic fallback — a missing key still never crashes an ingest. `writeDoxIndexFn` (test-only) replaces the LLM call; `logPath` defaults to `<wiki>/.state/llm-calls.json`. Never creates folders, moves pages, writes content pages, or decides taxonomy. Phase 7 additive: `WriteDoxOptions.language { input, output }` flows into `DoxIndexContext.language` and fills the folder prompt's `{languageDirective}` (vision `04` §9 — index prose in the output language); deterministic mode is unaffected. **Workspace pass (2026-07-20 amendment; per-wiki segments 2026-07-21):** `writeWorkspaceIndex({ workspace?, wikiSlug, doxLlm?, writeWorkspaceIndexFn?, outputLanguage?, logPath? })` re-composes `wikis/index-of-indexes.md` at the end of every ingest from PER-WIKI SEGMENTS — the topmost parent in the same bottom-up chain. The pass writes ONLY the triggering wiki's own contribution: one LLM call (`prompts/dox-writer-workspace.prompt.txt`, a per-wiki entry prompt whose only content input is the triggering wiki's freshly-written root index.md) produces a 1–3 sentence description in the run's output language, used for both the wiki's prose segment (`<!-- segment:<slug> -->` markers) and its `## Wikis` catalog line. Every other wiki's segments are preserved BYTE-FOR-BYTE (parsed by `parseWorkspaceSegments`; pre-segment files are migrated by seeding prose from existing catalog descriptions); wikis removed from disk lose their segments; missing segments get a fixed placeholder. Deterministic over ALL wikis every run: children (`<slug>/index.md` per wiki), statistics (wiki count + corpus totals), the fixed English framing line, and frontmatter (no `wiki` field). Fallback is per-wiki: LLM failure (≤3 attempts via `runWorkspaceEntryWithRetries`) → the first prose paragraph of the triggering wiki's root index. The LLM writes prose only — links are added deterministically, so no wikilink repair is needed at this level. **Prose model (2026-07-21b amendment):** the page's top prose is a coherent cross-wiki synthesis (`prompts/dox-writer-workspace.prompt.txt`, ALL wikis' root contracts) regenerated ONLY when the wiki set changed since the file's frontmatter children (add/remove) or no `<!-- workspace-prose -->` block exists — routine ingests preserve it byte-for-byte; the `## Wikis` catalog stays per-wiki owned (`prompts/dox-writer-workspace-entry.prompt.txt`, one line per wiki in that wiki's own language). Fallbacks are per-concern: `deterministicWorkspaceProse` for the prose, root-index first paragraph for the catalog line
