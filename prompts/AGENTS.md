# prompts/ — DOX contract

## Purpose

LLM prompt files for the agent pipeline (Extractor, Synthesis Writer, DOX Writer, AGENTS.md Updater). The Extractor prompt landed with Phase 2, the Synthesis Writer prompts with Phase 5, the DOX Writer prompt with Phase 6, and the AGENTS.md Updater prompt with Phase 9.

## Ownership

* `extractor.prompt.txt` — Phase 2: the Extractor's prompt. Fixed system instructions (8 extraction rules, entity page format, citation format per phase doc §2.1) + an explicit JSON-only OUTPUT FORMAT section (exact schema incl. the gates-2.9–2.12 extended fields `timeline`, `context`, `significance`, `disambiguation`) + runtime placeholders `{agentsMd}`, `{existingFolders}`, `{existingEntities}`, `{sourceFile}`, `{pageRange}`, `{chunkText}` substituted by `src/agents/extractor.ts`
* `synthesis.prompt.txt` — Phase 5: the strict entity Synthesis Writer's prompt. System instructions for writing a two-layer markdown article (readable synthesis + preserved detail sections) where every mention context, relationship evidence, and claim text appears verbatim in the output + runtime placeholders `{entityName}`, `{entityType}`, `{significance}`, `{disambiguation}`, `{mentions}`, `{relationships}`, `{claims}`, `{timeline}`, `{context}` substituted by `src/agents/synthesis.ts`; the wiki constitution `{agentsMd}` is appended by the agent before calling the LLM; the wikilink rule instructs the Obsidian-native pipe form `[[<entity-slug>|<Page Title>]]` (2026-07-20 user-directed change)
* `synthesis-permissive.prompt.txt` — Phase 5 (UAT refinement): the permissive entity Synthesis Writer fallback prompt. Used for dense entities where strict synthesis fails preservation; the model may summarize in Layer 1 but must preserve the exact mention contexts, relationship evidence, and claim text verbatim in the structured Layer 2 sections; same pipe-form wikilink rule
* `synthesis-topic.prompt.txt` — Phase 5: the strict topic Synthesis Writer prompt. System instructions for a two-layer topic article with readable synthesis at the top and verbatim `## Claims` / `## Sources` sections below + runtime placeholders `{topicName}`, `{entities}`, `{claims}`, `{sources}`, `{context}` substituted by `src/agents/synthesis.ts`; the wiki constitution is appended by the agent; same pipe-form wikilink rule
* `synthesis-topic-permissive.prompt.txt` — Phase 5: the permissive topic Synthesis Writer fallback prompt. The model may summarize in Layer 1 but must preserve the exact claim text verbatim in the `## Claims` section; same pipe-form wikilink rule. Phase 7 repair (2026-07-20): the template was missing its `=== TOPIC DATA ===` section entirely — `writePermissiveTopicSynthesis` filled `{topicName}`/`{entities}`/`{claims}`/`{sources}`/`{context}` into a template that contained none of them, so the live permissive-topic path would have sent a data-less prompt. The section was added byte-identical to `synthesis-topic.prompt.txt`'s data block (Verifier-confirmed minimal repair)
* `dox-writer.prompt.txt` — Phase 6: the DOX Writer's prompt, loaded and filled by `src/dox-writer.ts` and sent once per folder plus the wiki root. Explains the DOX Writer role (map, not territory) and the bottom-up flow (deepest folders indexed first; child folder indexes supplied to parents), defines two writing modes — (a) PAGES mode (folders with direct pages summarize those pages) and (b) SYNTHESIS mode (folders with child folders synthesize the child contracts into a parent-level description; both modes when a folder has pages AND children) — gives the exact output format (YAML frontmatter + body: title heading, rich description, `## Pages` + `## Navigation` for folders or `## Start Here` for the root, `## Statistics`), requires `## Pages` to catalog direct pages AND child folders (a zero-page parent still catalogs its child folders rather than emitting "No pages"), instructs verbatim use of the supplied children list, statistics, and EXACT LINK TARGETS (Obsidian-native pipe forms guaranteed to resolve by pure file lookup: `[[basename|Title]]` for pages, `[[<folder-path>/index|Title]]` for folder indexes, `[[index|Wiki Title]]` for the root — 2026-07-20 user-directed change), requires following the supplied wiki AGENTS.md writing rules (plain language, journalist test, no invented facts), and shows one pages-mode folder example, one synthesis-mode zero-page-parent example, and one wiki-level example (phase doc §3.3/§3.4). Runtime placeholders: `{wikiSlug}`, `{folderPath}` (`(root)` for the wiki root), `{folderTitle}`, `{children}`, `{subFolders}`, `{pages}`, `{childIndexes}`, `{navigation}`, `{linkTargets}`, `{statistics}`, `{pageContents}`, `{agentsMd}`, `{rollingMemory}`. Deterministic enforcement in `src/dox-writer.ts` always discards the returned frontmatter, replaces the `## Statistics` section, and normalizes/repairs/de-links wikilinks that are not already canonical pipe forms, so the prompt's prose quality matters but its frontmatter/counts/link forms are never blindly trusted
* `dox-writer-workspace.prompt.txt` — Phase 6 (2026-07-20 amendment; repurposed 2026-07-21b as the workspace PROSE prompt): loaded ONLY when the coherent workspace prose regenerates (wiki-set change or missing prose). Inputs: ALL wikis' freshly-written root `index.md` contracts + the run's output language; output: 3–6 sentences of coherent cross-wiki prose (no headings, lists, wikilinks, or frontmatter). Placeholders: `{outputLanguage}`, `{childIndexes}` — filled by `writeWorkspaceProseWithLlm` in `src/dox-writer.ts`
* `dox-writer-workspace-entry.prompt.txt` — Phase 6 (new 2026-07-21b): the per-wiki workspace catalog-line prompt, loaded once per ingest for the triggering wiki's `## Wikis` line. Its only content input is the triggering wiki's freshly-written root `index.md` contract; output: 1–3 sentences of plain prose (deterministic code adds the `[[<slug>/index|<Title>]]` link). Placeholders: `{wikiSlug}`, `{wikiTitle}`, `{outputLanguage}`, `{wikiRootIndex}` — filled by `writeWorkspaceEntryWithLlm`; empty/failed output retries ≤3 then falls back to the deterministic catalog line for the triggering wiki only
* `agents-updater.prompt.txt` — Phase 9: the AGENTS.md Updater's prompt, loaded and filled by `src/agents/agents-updater.ts`, sent once per `--update-agents` ingest. Instructs the model to return the COMPLETE updated wiki constitution as raw markdown (no fences, no commentary), keeping every existing section heading, with new folder examples added to `## Folder Structure`, new page types added as `## Page Types` table rows, nothing invented beyond the supplied inputs, and the `## Language` section preserved VERBATIM (Phase 7 binding — deterministic code in the agent ALSO re-imposes it over the output). Placeholders: `{currentAgentsMd}`, `{wikiStructure}`, `{newFolders}`, `{newPageTypes}`. This prompt does NOT carry the Phase 7 `{languageDirective}` block (compliance-log [2026-07-21 12:00] item 7): its additions are structural — folder paths and page-type names are already in the wiki's output language per the folder-naming rule — and the Language section is preserved verbatim rather than rewritten

## Local Contracts

* One prompt file per agent role, named `<agent>.prompt.txt`, created only by its implementing phase per the phase document
* Prompts are read by code in `src/`; keep them free of secrets and environment specifics
* Runtime placeholders use `{single-brace}` names (phase doc convention) — distinct from the `{{DOUBLE_BRACE}}` init-time placeholders in `templates/`; every placeholder must be substituted by the owning agent code before the call
* Phase 7 `{languageDirective}` contract (vision `04` §9.4): all six agent prompts (extractor, both entity synthesis, both topic synthesis, dox-writer) carry a `=== LANGUAGE ===\n{languageDirective}\n\n` block near the top, filled by the owning agent via `applyLanguageDirective` in `src/utils/language.ts` — non-empty directive replaces the placeholder; empty directive (both languages English) removes the WHOLE block so filled prompts stay byte-identical to pre-Phase-7. The workspace prompt (`dox-writer-workspace.prompt.txt`) does NOT carry it — it has its own `{outputLanguage}` placeholder per the 2026-07-20 amendment
* Prompt text must keep instructing: JSON-only output, folders only under `entities/`/`topics/` (max 3 levels below), lowercase kebab-case slugs, page numbers within the given range, empty chunk → empty arrays, and reuse of existing folders/entities from rolling memory — the Phase 2 gates depend on these behaviors
